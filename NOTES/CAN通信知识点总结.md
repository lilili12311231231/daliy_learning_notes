# CAN 通信知识点总结

> 基于正点原子「实验27 CAN通信实验」（STM32F407 HAL 库）

---

## 一、CAN 是什么

- **全称**：Controller Area Network（控制器局域网）
- **主要应用**：汽车电子、工业自动化（不是医疗器械）
- **特点**：**多主总线**——一条总线上挂几十个节点，谁都能主动发消息，靠仲裁避免冲突

### 和 UART（串口）的区别

| 对比项 | CAN | UART |
|---|---|---|
| 拓扑 | 多主总线，一对多 | 点对点，一对一 |
| 物理线 | CAN_H + CAN_L 差分双绞线 | TX + RX |
| 抗干扰 | 差分信号，很强 | 单端信号，弱 |
| 错误处理 | 硬件 CRC 校验 + ACK 应答 + 自动重发 | 什么都没有 |

---

## 二、硬件基础

- 通信靠 **CAN_H** 和 **CAN_L** 两根线（双绞线）
- **差分信号抗干扰原理**：
  1. 两根线传**相反的电压**（CAN_H 高时 CAN_L 低）
  2. 接收端判断的是 `CAN_H - CAN_L` 的**差值**
  3. 外部电磁干扰会**同时**叠加到两根线上
  4. 两根线涨了同样的干扰 → 做减法时干扰**被抵消**
  - 这叫「抗共模干扰」，是 CAN 在汽车强干扰环境下能稳定工作的根本原因
- **终端电阻**：总线两端各接一个 **120Ω**

---

## 三、工作模式

| 模式 | 含义 | 使用场景 |
|---|---|---|
| 回环（LoopBack） | 自己发自己收 | 一块板子就能自测，学习和调试用 |
| 普通（Normal） | 两个节点互相收发 | 需要两块板子连 CAN 总线 |

**实验默认用回环**，因为不需要外接第二块板子，就能验证 CAN 外设配置是否正确。

---

## 四、位时序（重点难点）

一个位（1 bit）的时间被切成很多小份，每份叫 **TQ（时间量子）**：

```
|-- 同步段 SS --|-- 时间段1 BS1 --| 采样点 |-- 时间段2 BS2 --|
     1 个 TQ          7 个 TQ                  6 个 TQ
```

- **同步段 SS**：固定 1 个 TQ，是每一位的起点，用来对齐时钟（这个才是「同步」）
- **BS1（时间段1）**：采样点**之前**的部分
- **BS2（时间段2）**：采样点**之后**的部分（不是「校验」）
- **采样点**：在 BS1 和 BS2 交界处，此刻才真正判断这一位是 0 还是 1
- **SJW（同步跳跃宽度）**：两个节点晶振频率有微小误差，接收方可以在这位上「伸长/缩短」来重新对齐，SJW 就是允许调整的**最大范围**

> 一句话：SJW 不是「同步段」，是「允许同步调整的宽度」；BS2 也不是校验，是采样点之后的尾巴。

---

## 五、波特率计算

```
波特率 = fAPB1 / (brp × 总位时间)
总位时间 = 同步段 + BS1 + BS2 = 1 + 7 + 6 = 14 个 TQ
```

代入实验参数（APB1 = 42MHz，brp = 6）：

```
波特率 = 42MHz / (6 × 14) = 42M / 84 = 500Kbps
```

> 注意是 `(1 + 7 + 6)`，同步段固定占 1 个 TQ，这个 **+1** 别漏。

## 六、can_init 函数参数

函数原型：

```c
uint8_t can_init(uint32_t tsjw, uint32_t tbs2, uint32_t tbs1, uint16_t brp, uint32_t mode)
```

调用：

```c
can_init(CAN_SJW_1TQ, CAN_BS2_6TQ, CAN_BS1_7TQ, 6, CAN_MODE_LOOPBACK)
```

逐个对应：

| 实参 | 形参 | 含义 | 值 |
|---|---|---|---|
| CAN_SJW_1TQ | tsjw | 同步跳跃宽度 | 1 |
| CAN_BS2_6TQ | tbs2 | 时间段2 | 6 |
| CAN_BS1_7TQ | tbs1 | 时间段1 | 7 |
| 6 | brp | 分频系数（uint16_t） | 6 |
| CAN_MODE_LOOPBACK | mode | 工作模式 | 回环 |

> 注意：**第 4 个参数 brp 才是 uint16_t**；顺序是 **tbs2 在前、tbs1 在后**，容易看反。

## 七、帧结构

- **标准帧**：ID 是 **11 位**
- **扩展帧**：ID 是 **29 位**
- **ID 的作用**（不是「地址」，不是「发给谁」）：
  1. **仲裁**：多个节点同时发时，ID 小的优先级高
  2. **过滤**：接收节点看 ID 决定要不要收这条消息
  3. **标识消息内容**（比如「发动机转速」用某个固定 ID）
- 实验发送用的 ID = **0x12**

### DLC（数据长度码）

- Data Length Code，表示数据段有几个字节
- 取值范围 **0~8**，对应数据 0~8 字节
- 实验发送 8 字节，所以 **DLC = 8**

---

## 八、过滤器与掩码

- CAN 是**广播**的，总线上所有节点都能收到所有消息
- 过滤器根据 **ID 筛选**：ID 匹配的收下，不匹配的硬件直接丢弃（不打扰 CPU）
- 过滤器有两个值：**过滤 ID**（期望的 ID）+ **掩码**（决定哪些位要较真）

**掩码规则**：

| 掩码这一位 = | 含义 |
|---|---|
| **1** | 较真：ID 这一位必须和「过滤 ID」对应位**完全一致** |
| **0** | 放水：ID 这一位**不管**，是 0 还是 1 都通过 |

**效果对照**：

| 掩码配置 | 效果 |
|---|---|
| 全 0（0x0000） | **全通过**，任何 ID 都收（实验里就是这种） |
| 全 1（0x7FF 标准帧） | 最严格，只收 ID 完全等于「过滤 ID」的那一帧 |

---

## 九、收发流程

```c
uint8_t can_send_msg(uint32_t id, uint8_t *msg, uint8_t len);   // 发送
uint8_t can_receive_msg(uint32_t id, uint8_t *buf);             // 接收（查询）
```

- 发送端和接收端靠 **ID** 匹配，判断「这帧是不是我要收的」
- **ACK 应答**：接收节点正确收到后，会在帧的 ACK 段应答，发送端据此知道发送成功

## 十、实验现象回顾

1. **上电**：LCD 显示标题、模式提示、Count / Send Data / Receive Data 三行数据区
2. **Count 自动累加 + LED0 闪烁**：每 200ms，Count +1，LED0 翻转（系统心跳，表示程序在跑）
3. **按 KEY0**：发送 8 个字节（内容是 `cnt, cnt+1, ..., cnt+7`），回环模式下自己立刻收到，Send Data 区和 Receive Data 区显示**相同**的数字，并显示 "OK"
4. **按 WK_UP**：在回环模式 / 普通模式之间切换

> 为什么每次按 KEY0 数据会变？因为 `canbuf[i] = cnt + i` 里的 `cnt` 一直在自动累加。

## 十一、易错点清单（编译时踩过的坑）

- `can.h` / `can.c` 手写时大量笔误：`g_canx_rxheader` 写错成 `g_canny_rxheader`、`StdId` 写成 `Stdid`、`CAN_RX` 写成 `CAN_Rx`、宏名 `CAN_RX0_INT_ENABLE` 写错、`HAL_CAN_GetRxFifoFillLevel` 写成 `FIllLevel` 等
- `key_scan()` 必须带参数 `key_scan(0)`
- 常量名是 `WKUP_PRES`（不是 `WAKE_PRES`）
- USMART 组件 + HAL 库的 `stm32f4xx_hal_can.c` 等源文件要 Add 进 Keil 工程
