STM32F407 通用定时器输入捕获 — 问题汇总
========================================

问题 1：编译错误 — 缺少头文件和变量声明
----------------------------------------
现象：
  main.c 报 "implicitly declared" 和 "identifier undefined" 错误

根因：
  - gtim.h 缺少 gtim_timx_cap_chy_init 函数声明
  - gtim.h 缺少 g_timxchy_cap_sta 和 g_timxchy_cap_val 的 extern 声明
  - main.c 缺少 key.h 的 include

修复：
  - gtim.h 中补充函数声明和 extern 变量声明
  - main.c 中添加 #include "./BSP/KEY/key.h"


问题 2：编译错误 — 头文件路径错误
----------------------------------------
现象：
  cannot open source input file "usart.h"

根因：
  错误地添加了 #include "usart.h"，正点原子工程的头文件路径是 ./SYSTEM/usart/usart.h

修复：
  删除多余的 include，保留原有正确的相对路径引入


问题 3：文件编码被破坏
----------------------------------------
现象：
  main.c 和 gtim.h 的中文注释变成乱码

根因：
  Edit 工具将 GBK 编码文件转成了 UTF-8，Keil 编译器期望 GBK 编码

修复：
  用 iconv 将文件转回 GBK 编码


问题 4：程序下载后 LED 不闪烁、串口无输出
----------------------------------------
现象：
  编译通过下载后完全无反应，LED 不闪烁，串口无输出

根因：
  stm32f4xx_it.c 中缺少 TIM5_IRQHandler 中断服务函数。
  TIM5 触发中断后跳转到启动文件的弱定义 Default_Handler（死循环 B .），程序卡死。

修复：
  - stm32f4xx_it.c 添加 TIM5_IRQHandler，调用 HAL_TIM_IRQHandler(&g_timx_cap_chy_handle)
  - gtim.h 添加 extern TIM_HandleTypeDef g_timx_cap_chy_handle


问题 5：捕获值始终为 65536 的整数倍
----------------------------------------
现象：
  串口打印的脉宽值全是 65536 的整数倍（如 262144、524288、589824）

根因：
  HAL_TIM_IC_CaptureCallback 中使用了未初始化的 g_timx_cap_chy_handler，
  正确初始化的句柄是 g_timx_cap_chy_handle。
  未初始化的句柄读 CCR 寄存器始终返回 0，导致 捕获值 = 溢出次数 * 65536 + 0

修复：
  删除多余的 g_timx_cap_chy_handler，所有引用统一改为 g_timx_cap_chy_handle


涉及文件改动清单
----------------------------------------
  User/main.c                        删除多余 include，添加 key.h，uart_init -> usart_init
  User/stm32f4xx_it.c                添加 TIM5_IRQHandler
  Drivers/BSP/TIMER/gtim.h           添加函数声明、extern 变量声明、extern 句柄声明
  Drivers/BSP/TIMER/gtim.c           删除重复句柄，统一句柄引用
  Drivers/BSP/KEY/key.c              重写，支持 WK_UP/KEY0/KEY1/KEY2 四个按键
  Drivers/BSP/KEY/key.h              重写，添加按键引脚宏定义


最终结果
----------------------------------------
  按下 WK_UP 按键（PA0），串口正常打印高电平持续时间，范围约 110ms ~ 180ms，
  输入捕获功能工作正常。
