# 工业采集终端 — 面试高频问点

> 项目链路：STM32 ADC/DMA 采集 → Modbus-RTU 从站 → RS485 差分总线 → 树莓派读 Modbus → Flask+SocketIO 监控大屏 → systemd 常驻 → cpolar 外网穿透

按模块整理，每个问题给「考点 + 精炼答案」，面试时能背出来、也能被追问。

---

## 一、项目整体

**Q：一句话介绍你的项目？**
采集端 STM32 用 ADC+DMA 多路采集（电压/温度/光强），做数字滤波后，通过 Modbus-RTU 从站协议，经 RS485 差分总线把数据发给树莓派主站；树莓派跑 Flask+SocketIO 网页实时显示，systemd 常驻，cpolar 穿透到外网。

**Q：完整数据流走一遍？**
传感器/电位器 → ADC 采样（DMA 搬进 RAM 数组）→ 滤波 → 写进 Modbus 保持寄存器 → 树莓派发 Modbus 读请求 → RS485 差分传数据 → 从站回响应帧 → 树莓派解析 → SocketIO 推给浏览器 → 网页实时更新。

**Q：为什么报警判断放在 STM32 而不是网页端？**
「边端判断」——采集端第一时间判断，不依赖网络和上位机，掉线时数据更可信。网页只负责显示。

## 二、ADC / DMA 采集

**Q：ADC 是多少位？满量程对应多少？**
F407 的 ADC 是 12 位，满量程 0~4095。电压换算公式：`电压 = raw / 4096 × 3.3V`。

**Q：采样时间是什么？影响什么？**
采样时间 = ADC 内部采样电容充电的时间。时间越长，电容充得越满，结果越准，但速度越慢。这是「精度 vs 速度」的权衡。

**Q：轮询、中断、DMA 三种读取方式区别？**
- 轮询：CPU 一直等，占满 CPU，但简单。
- 中断：转换完成触发中断，CPU 再去读，省了等待时间。
- DMA：数据自动搬到内存数组，CPU 几乎不参与，适合多路、高速采集。

**Q：DMA 循环模式是什么？**
DMA 把 ADC 结果连续搬进一个数组，搬完一圈自动从头再搬，形成循环缓冲，永远是最新的一批数据。

**Q：连续转换 和 单次转换 区别？（高频，容易混）**
- 单次转换：触发一次，转换一次，然后停。
- 连续转换：一次触发后不停转换，配合 DMA 才能持续搬数据。
- 关键：DMA 只是「搬运工」，它不决定 ADC 是否转换。连续转换才决定 ADC 持续产数据。

**Q：采到的数据存在哪？**
存在 RAM 的数组里（result 数组），不是 Flash。Flash 是存程序的，掉电不丢；RAM 是运行时的，掉电丢。

**Q：ADC 原始值为什么不能直接用？**
有噪声、有毛刺，直接传会跳。要先滤波，再标定成物理量。

## 三、Modbus-RTU 协议

**Q：Modbus-RTU 帧格式分几部分？**
地址（1 字节）+ 功能码（1 字节）+ 数据（n 字节）+ CRC 校验（2 字节）。

**Q：主从模型是什么？**
一个主站（这里树莓派），多个从站（STM32）。从站从不主动发数据，只有主站问，从站才答。

**Q：功能码 03 是什么意思？**
读保持寄存器。请求 `01 03 00 00 00 03 05 CB` 意思是：从站 01，读从地址 0x0000 开始的 3 个寄存器。

**Q：响应帧长什么样？**
`01 03 06 + 6 字节数据 + 2 字节 CRC`。其中 06 是数据字节数 = 寄存器数 × 2（每个寄存器 2 字节）。

**Q：CRC 是干嘛的？**
CRC16 校验，检查帧在传输中是否出错。算出来的 CRC 和帧里的对不上就丢弃这一帧。串口助手勾了「发送新行」会在末尾加 \r\n，导致 CRC 校验失败收不到响应。

**Q：字节序大小端怎么理解？（高频，易错）**
内存里是「小端」：低字节放低地址。Modbus 线上是「大端」：高字节先发。所以 329 在内存里存 `49 01`，但在线上发 `01 49`（0x0149 = 329）。方向别记反。

**Q：保持寄存器 vs 输入寄存器？**
- 保持寄存器（03/06 功能码）：可读可写，比如设备地址、波特率。
- 输入寄存器（04 功能码）：只读，比如采集值。
- 采集值用 03 还是 04 看设计，但要知道区别。

**Q：帧之间怎么区分边界？**
靠 3.5 个字符时间的静默间隔。超过这个静默时间，就认为一帧结束。

## 四、RS485 差分总线

**Q：RS485 为什么抗干扰？**
差分信号：传 A、B 两根线，靠 A-B 的电压差表示 0/1。干扰会同时加在 A、B 上（共模干扰），相减就抵消了。RS232 是单端对地，抗干扰差。

**Q：半双工是什么意思？方向怎么控制？**
同一时刻只能收或只能发，不能同时。用 DE/RE 引脚控制方向：高电平 = 发送，低电平 = 接收。

**Q：方向控制的坑在哪？**
发送完最后一个字节，要等它**移位发送完毕**才能把 DE 拉低，否则最后一个字节会被截断。

**Q：120Ω 终端电阻加在哪？**
只在总线**两端**各加一个，中间节点不加。加多了总线负载重、信号畸变。

**Q：A/B 接反会怎样？**
差分极性反相，从站 CRC 校验失败，静默丢帧，表现就是「完全收不到数据」。对调 A/B 即通。

**Q：A/B 偏置电阻是干嘛的？**
空闲时总线电平不确定，加偏置让 A>B（空闲为逻辑 1），否则第一个字节容易收到乱码 0xFF。

**Q：隔离解决什么？**
用隔离收发器（如 ADM2483）把现场强电和 MCU 电气隔开，防止浪涌烧坏 MCU。工业现场标配。

## 五、滤波与标定

**Q：中值滤波和滑动平均各治什么？**
- 中值滤波：排序取中间值，专治偶发尖峰毛刺。
- 滑动平均：队列求和平均，让数据平滑，治随机抖动。
- 本项目两级级联：先中值去毛刺，再滑动平均平滑。

**Q：两级级联为什么这个顺序？**
先用中值把尖峰干掉，剩下的随机噪声再用平均平滑。反过来的话，一个尖峰会被平均摊进结果里污染数据。

**Q：滤波器启动时怎么初始化？**
用第一个采样值填满整个窗口，避免启动时从 0 慢慢爬升。

**Q：标定是什么？**
把 ADC 原始值换算成物理量。线性关系 `y = kx + b`：
`物理量 = (ADC值 - 零点ADC) × 满量程 / (满量程ADC - 零点ADC)`。
用实际测的零点和满量程两个点，算出斜率和截距。

**Q：为什么不假设 ADC 0 就对应物理量 0？**
运放有零点漂移、传感器有失调，ADC 0 时物理量往往不是 0，所以要实测零点。

**Q：传小数怎么办？**
MCU 上避免浮点，把物理量放大 10 或 100 倍用整数存，传的时候约定好缩放。Modbus 寄存器是 16 位整数，传小数必须缩放。

## 六、看门狗

**Q：看门狗是干嘛的？**
程序跑飞或死循环时，没人喂狗，超时后自动复位 MCU，让设备自恢复。

**Q：IWDG 时钟从哪来？**
LSI 内部低速时钟 32kHz，独立于主时钟，即使主时钟挂了狗也能工作。

**Q：为什么用寄存器操作而不是 HAL？**
HAL 的 IWDG 模块默认被注释掉，要走 HAL 得改 hal_conf.h 再加库文件。寄存器操作只改 main.c，更可控。

**Q：看门狗调试的坑？**
IWDG 一旦启动就无法软件停止，在线调试断点一停就不喂狗，会触发复位。所以必须直接烧录运行，不能挂断点。

## 七、IoT 可视化（树莓派侧）

**Q：树莓派在整个项目里扮演什么角色？**
Modbus 主站 + Web 服务器。用 pyserial 开串口、minimalmodbus 发读请求，轮询 STM32 的三路寄存器，然后 Flask+SocketIO 实时推给浏览器。

**Q：为什么要单独开一个线程读串口？**
读串口设了超时（timeout=1s），如果放在网页请求的处理线程里，会卡住网页响应。单独开线程，网页和读数据互不干扰。

**Q：SocketIO 怎么实现实时推送？**
后端 `socketio.emit('data', ...)` 把数据广播出去，前端 `socket.on('data')` 接收更新页面。用了 threading 异步模式，不依赖 eventlet/gevent。

**Q：systemd 常驻解决了什么？**
进程崩溃自动重启（Restart=always + RestartSec=5），开机自启（enable）。`enable`（登记开机自启）和 `start`（立即启动）是两回事。

**Q：cpolar 内网穿透原理？**
本地服务通过隧道映射到公网 URL，外部通过这个 URL 访问内网的 5000 端口网页。免费版 URL 每次重启会变。

## 八、开放性问题（面试官最爱追问）

**Q：这个项目最难的一个点是什么？**
（按自己真实经历答，下面几个都是真实踩过的坑，挑一个讲透）
- RS485 方向控制：正点原子跳线帽命名反直觉，RS485_RX 其实接 MCU TX，不看原理图凭丝印猜会走弯路。
- A/B 接反导致静默丢帧，差分极性反相 CRC 失败。
- 光敏 ADC 单次转换没配好，连续转换溢出导致数据冻结在旧值。

**Q：如果要加一路传感器，改哪些地方？**
1. 硬件接新传感器到 ADC 通道；
2. STM32 加一路 DMA 采集 + 滤波；
3. 写进一个新的保持寄存器地址；
4. 树莓派读寄存器数量 +1；
5. 网页加一张卡片/曲线。

**Q：从站（STM32）不回复了，你怎么排查？**
从物理层往上查：先看 STM32 有没有上电 → 查 A/B 有没有接反 → 查方向引脚极性 → 查波特率是否一致（Modbus 默认 9600）→ 最后查 CRC 帧格式。

**Q：数据延迟大概多少？瓶颈在哪？**
采集端滤波引入的延迟 + 树莓派 1 秒轮询周期。瓶颈在轮询频率，工业场景要更快可以减小轮询间隔或改事件触发。
